The 2020 derecho, measured field by field

On August 10, 2020 a line of 100+ mph wind crossed Iowa and flattened corn for 200 miles. I built a pipeline that scores the damage on every USDA field boundary it touched, from public satellite data, on open-source Spark, Sedona and Iceberg, for about ten dollars of compute.

01WhyDrought Monitor D1 coverage in Iowa went from 34.3% to 60.9% inside the same 15 days.

Nobody had a field-level number

After the storm, working out which fields lost canopy took weeks and a GIS desk. Insurers, agronomists and USDA all needed the same number and none of them had it. The imagery was already public. What nobody had done was run it against every field boundary in the state and keep the provenance on each value.

Computing greenness is easy. The problem is that August 2020 was also a flash drought. Drought Monitor coverage nearly doubled inside the study window, so a raw before-and-after picture charges the drought to the storm. An honest damage number has to subtract what the drought did to fields the wind never reached.

02Methodconfig.yml is in git. The commit that set these thresholds predates the first result.

How the number gets made

I fixed every threshold in config.yml before there was a result to tune them against, and the commit history shows it. If I didn't measure it, it didn't happen.

  1. Mask per pixel

    Sentinel-2 scenes from before the storm (Aug 4) and after it (Aug 19). Cloud and shadow come out per pixel using the scene classification layer, and I compute NDVI on whatever survives.

  2. Score per field boundary

    One zonal pass scores all 7,226 USDA field boundaries in the demo county. Each field gets a mean NDVI and a valid_frac, the share of that field that survived masking.

  3. Subtract the drought

    I compare each storm-hit corn field against corn fields outside every wind polygon at matched latitude, five controls minimum. What's left is the storm.

I checked the data before I touched the method. The Benton County subset of the statewide warehouse reproduces Table 1 to four decimals, out of a warehouse built by completely different infrastructure: a Graviton spot fleet and a rewritten join, against a laptop and a broadcast spatial join.

What broke was the matching. I matched controls on latitude alone, which cancels the drought inside one county and doesn't cancel it across three tiles of longitude. The drought was worse in western Iowa, the 80-99 band reaches far west (its estimate runs -0.141 in its western third against -0.040 in its eastern third), and the 100+ core near Cedar Rapids has no western fields at all. The middle band was picking up drought that nothing controlled for.

Add longitude to the match and the gradient comes back, at magnitudes that agree with the county study. I labeled that fix post-hoc and dated it, and the pre-registered analysis stays the result of record. The check that caught this was written before I had results.

05LimitsThe filter drops a field entirely rather than guessing a value for it.

What the cloud mask throws out

A field renders grey when cloud masking leaves less than half of it observable on either date. There's no gap-filling and no max-value compositing here. Picking the healthiest-looking date would drag measured damage toward zero.

Attrition is worse in the hardest-hit bands because storms leave cloud behind, so the surviving sample isn't random with respect to damage. Optical NDVI also understates lodging, since flattened corn stays green for weeks. Both bias the estimate the same way, so these numbers are floors.

07RuntimeTable 4. One image, laptop through cluster.

One container, laptop to cluster

The pipeline is Apache Spark 3.5, Apache Sedona 1.9.1 and Apache Iceberg. The same image runs every tier below: spark-submit local[4] on a laptop, a Kubernetes cluster with driver and executor pods (verified on both native submit and the Spark Operator CRD), and EC2 in us-west-2, in-region with the Sentinel-2 archive. Runs are incremental by design: they diff against the Iceberg manifest and process only what changed.

08Run itThe demo tier needs no cloud account and no credentials.

Reproduce this for nothing

The demo tier runs end to end on a laptop in about seven minutes against the public Sentinel-2 archive. Each run finishes on a Great Expectations gate, and a failure stops the run instead of publishing.

git clone https://github.com/owensross27/s2-field-ndvi
cd s2-field-ndvi && make setup && make data
make pipeline     # 01 fields, 02 scenes, 03 ndvi, 04 publish, 05 dq gate
make web-serve    # this page and the map at localhost:8137
